# Runtime floors + the one ceiling that matters.
#
# pandas <3 is deliberate, not incidental. CLAUDE.md requires that identical
# code run unchanged on laptop, Kaggle, Colab and Aqua; those base images ship
# pandas 2.x, while a bare ">=2.0" resolves to 3.0.x here. pandas 3.0 changed
# the default string dtype and made copy-on-write unconditional, so developing
# against it would silently produce code the other tiers cannot run.
# The Phase 0 acceptance test is verified green on BOTH 2.3.x and 3.0.x.
#
# anndata floor is >=0.12.10 to match what cell-eval (Phase 5 scorer) requires,
# so the judge env and the scorer env cannot resolve to incompatible anndatas.
anndata>=0.12.10
scanpy>=1.10
scipy>=1.11
numpy>=1.26
pandas>=2.2,<3
pyarrow>=14
pyyaml>=6

# The competition's own scorer. Phase 4 computes reference DE with its routine
# and Phase 5 wraps its vcc2026 preset, so reference DE and scored DE cannot
# drift -- CLAUDE.md requires them to be the same code path. It was installed
# ad hoc locally and therefore missing on Kaggle, where Phase 4's DE step died
# on `import cell_eval2` after the deltas had already been computed.
# ⚠️ cell-eval2, NOT cell-eval: the latter is the 2025 scorer (18,080 genes).
cell-eval2>=0.16

# cell-eval2's fast CPU DE backend. Without it cell-eval2 falls back to scanpy,
# which is ~10x slower: K562's DE hit Kaggle's 12-hour session limit at shard
# 19 of 20 on scanpy. Verified to produce IDENTICAL nreal to scanpy on a
# matched slice (8/8 perturbations exact), so this is pure speed, not a
# different answer. Needs numpy>=2.4.2 / pandas>=2.3.3 -- satisfied here, but
# NOT on requirements-aqua.txt's glibc-2.17 ceilings, which is fine: Aqua is
# no longer the run-big tier.
pdex>=0.3
